# 双目 RAW 原始帧导出：RK 使用说明

这是独立临时采集工具，不安装新系统，不依赖 Python，不替换 YOLO。它需配合本包的 `raw_calibration.fs`，不能直接读取生产 RGB 位流。

## 1. 安装与加载

将 `raw-calibration-rk3588-20261029.tar.gz` 放到 RK 的 `/root`，逐条执行：

```sh
cd /root
tar -xzf raw-calibration-rk3588-20261029.tar.gz
cd /root/raw-calibration-rk3588-20261029
sh install.sh
```

先退出原 YOLO 窗口和摄像头 ISP 服务。两个镜头同时朝向**稳定、均匀、不闪烁的亮场**，再从电脑通过 Gowin Programmer **SRAM 下载**本包的 `raw_calibration.fs`。不要先盖住镜头上电，暗处自动曝光会选择不合适的参数。临时工程不输出 YOLO 画面，不运行 IMU/导航；电机 PWM/方向脚固定 0。

加载后约 10 秒，再执行：

```sh
sh /root/raw-calibration/prepare-network.sh eth0
/root/raw-calibration/rawcap --interface eth0 info
/root/raw-calibration/rawcap --interface eth0 stats --frames 5
```

内部 RGMII 默认 `eth0`。如实际接口不同，将三处 `eth0` 改成内部 FPGA 链路接口。不要改成手机 Wi-Fi 接口。工具使用原始以太网接收，无需手动配置静态 IP。

`info` 输出应有 `ready: true`、两路 `locked: true`、`raw_bits: 8`、`width: 960`、`height: 1080`，并保存完整寄存器值。`exposure_lines` 是曝光行数，`gain_code` 是寄存器编码，不能直接当倍数。`BGGR` 沿用 flip=1/mirror=0 的配置解释，实物颜色相位仍需测试确认；RAW 保存不做颜色重排。

## 2. 先亮帧，再暗帧

保持亮场，采集 16 帧/眼：

```sh
/root/raw-calibration/rawcap --interface eth0 capture --kind flat --frames 16 --out-dir /root/raw-cal
```

然后盖住两个镜头，保持板子运行，不重新加载位流、不重置相机。等约 1 秒，采集暗帧：

```sh
/root/raw-calibration/rawcap --interface eth0 capture --kind dark --frames 16 --out-dir /root/raw-cal
```

两组的曝光、增益、白平衡从亮场锁定时起保持相同。暗帧命令自动读取同目录 `profile-flat.json` 核对；不一致就拒绝保存。

每次默认先丢弃 3 个完整帧，再保存 16 帧。如需单帧用 `--frames 1`；默认总等待超时为 60 秒，可用 `--timeout 120` 调整。不会覆盖已有结果，再采一组请换目录，例如 `/root/raw-cal-02`。

生成六个文件：

| 文件 | 内容 |
| --- | --- |
| cam0-flat.raw / cam1-flat.raw | 两路亮帧，各 16,588,800 字节 |
| cam0-dark.raw / cam1-dark.raw | 两路暗帧，各 16,588,800 字节 |
| profile-flat.json / profile-dark.json | 两路参数、帧数、尺寸、丢帧统计及完整锁定快照 |

RAW 无文件头、8 bit/像素、按行连续、16 帧直接串接；**一帧 1,036,800 字节**。四个 RAW 共约 66.4 MB，至少预留 100 MB 可用空间。可执行 `wc -c /root/raw-cal/*.raw` 核对大小。

cam0 对应开发板 **CAM1 接口/生产 eye0**，cam1 对应 **CAM2 接口/生产 eye1**。物理左目/右目请用 `stats` 时短暂遮住一只镜头观察哪个均值下降来确认，随后恢复亮场。若不确定先按端口编号保存，不要按文件名猜左右。两路是等行号配对，旧协议没有传感器源帧 ID，适用于静态暗场和亮场，不用于动态双目同步测量。

## 3. 采集后恢复

把 `/root/raw-cal` 的六个文件完整拷回电脑。完成后可恢复网络临时设置：

```sh
sh /root/raw-calibration/restore-network.sh eth0
```

加载原来的生产 `.fs`，按原流程启动 YOLO/ISP。没有改生产 Flash 时，正常重新上电也会回到 Flash 中的工程。

**标定表的使用条件**：原生产工程重新初始化后会恢复自动曝光/增益等流程。若要把这组暗/亮帧用于 FPN，生产运行也应使用相应锁定设置；不能把一次标定当作对任意曝光通用。下面的 PC 工具可生成单独的生产工程副本。

## 4. PC 生成标定表及独立锁定工程

以下命令在电脑执行，RK 不需要 Python。包内 `pc-tools` 包含原 v40 的离线系数工具；RAW 输入只需 Python3 标准库，NumPy 仅在使用 `.npy` 输入时需要。示例假设六个文件已拷到电脑 `raw-cal` 目录：

```sh
python3 pc-tools/fpc1.py prepare --eye 0 --locked-capture --dark raw-cal/cam0-dark.raw --bright raw-cal/cam0-flat.raw --output fpn-eye0.json
python3 pc-tools/fpc1.py prepare --eye 1 --locked-capture --dark raw-cal/cam1-dark.raw --bright raw-cal/cam1-flat.raw --output fpn-eye1.json
```

亮场不能是普通有纹理的场景。观察统计输出，避免大量饱和；离线工具还会检查最小暗亮差和 Bayer 奇偶行均值一致性。若过暗、饱和或照明有纹理，应调整亮场后**重新加载采集位流**，重新采完整一组。

需要生产端匹配采集参数时，在完整源码仓库中执行（输出目录必须不存在）：

```sh
python3 rk3588/raw_calibration_standalone/make_locked_runtime.py --profile raw-cal/profile-flat.json --source fpga/robot_image_v40 --output fpga/robot_image_v40_calibrated
```

它仅复制并追加真实曝光/增益/WB 设置，不修改原工程，不自动烧板；然后打开新目录的 `.gprj` 完整编译。必须重新检查时序并上板确认。工具限制使用本仓库原 v40 传感器表，遇到其他版本会拒绝，避免盲目拼接。此采集工程不加载 AF 固件，生产对焦、黑电平等仍需实物核对。

## 5. 常见提示

- `python3: not found`：本采集流程不运行 Python，使用 `/root/raw-calibration/rawcap`。
- `Set internal interface MTU first`：先执行 `prepare-network.sh`。单个 RAW 行的 IP 包 1950 字节，大于普通 MTU。
- `camera setup failed`：查看其中 cam0/cam1 的 error 和 register。1=NACK，2=ID，3=锁定位，4=参数变化，5=内部状态，6=事务超时。检查两只相机后重新加载临时位流。
- 长时间等不到帧：确认加载的是本临时位流、两只相机均连接、内部链路接口选对、MTU 已设置，原 ISP/YOLO 已退出。只有两眼都锁定才发送 RAW。
- `incomplete`：缺行或乱序的整帧已丢弃，不会补零冒充完整帧。持续发生需检查链路/接收负载。
- `settings differ`：暗亮之间发生重启或设置变化。重新对亮场加载位流，从亮帧开始采。
- `already exists`：选择新输出目录；不覆盖旧标定。
- `directory is busy`：另一个采集在运行，或强制掉电留下 `.capture.lock`。先确认没有正在采集，检查旧 `.part` 后换新目录采集。正常失败会清理未完成临时 RAW；JSON 是整组完成标志。

## 源码和验证范围

`src/rawcap.cpp` 是完整接收程序；`build.py` 为 PC BSP 静态交叉编译脚本，支持 `CROSS_COMPILE=/完整工具链前缀/aarch64-none-linux-gnu-`。交付二进制实际为静态 AArch64，不需安装额外 C++ 动态库。

离线测试涵盖完整 DVP→FIFO→UDP 数据和 ARM64 二进制回放，但**尚未实物上板采集验证**。FPGA 已完整布局布线并通过所声明的内部时序检查；外部 DVP/RGMII 接口窗口仍需实物验证。测试报告随包提供，不把仿真结果当实测。
