v23.2 导航定位时间对齐修复

现场依据
用户状态中的具体故障为 encoder_jump_or_imu_reset；随后 IMU fresh=1、cal=done、bias_valid=1，编码器 illegal=0、restarts=0。
这些日志证明导航已经锁定了跳变故障，不能单凭手机通用提示认定 IMU 没校准；日志没有记录触发那一包的原始差值，因此不能声称已完整复现现场全部原因。

已复现的程序问题与修正
1. 原程序把异步 HTTP 中最新 yaw 直接绑定到 SNS 的收包时刻。SNS 不仅每50ms上报，还会在超声波状态变化时按1ms节拍额外上报；正常 yaw 的一次快照更新可能落在很短的 SNS 间隔上，触发虚假的角度跳变。
   新程序读取原接口中已有的 imu.timestamp_ms/sequence，与 SNS.uptime_ms 在 FPGA 毫秒时基上对齐，只用两侧已接收的源样本插值；不外推，不把重复快照当新 IMU 样本。
2. FPGA 两计时器来自同一50MHz域。IMU计数器比SNS晚释放几个时钟周期，差值小于1ms。无需修改FPGA协议或位流。
3. 设备时间用于计算运动间隔；真实内核收包时间仍用于判断新鲜度。两者不能混用。
4. 内部一次短 HTTP 超时不再被转换成一帧伪造的 imu_valid=false。等待期间不刷新旧数据的新鲜度，真正超过原250ms期限仍停机；控制网关自身的失联与电机停机流程保持有效，通信恢复不会自动重新使能或开始任务。
5. 显式地图/轮组重置后拒绝旧请求快照和旧收包，等待重置之后的新基线。启动校准尚未完成时可以继续等待；已建立的地图或已锁定故障不会自行恢复。
6. 角度跳变、编码器跳变及其他首次故障分别记录。NAV/status.json 新增 localization 与 input_alignment，包含源序号、源时间、运动间隔、角度差、轮位移差和原阈值。

保护与限制
原有最大角速度、轮速、250ms数据超时、编码器同侧持续差异、超声波有效性、未知区域停车和地图清障要求保持有效。
未放宽阈值，未自动清除定位故障，未自动确认标定。旧误判地图不能继续沿用，应重新启动并建图。
历史 illegal_seen 位的协议语义仍需单独改进；本次现场为0，本补丁保持其现有保守拒绝处理，没有将该硬件诊断位忽略。
用户日志中前、左超声波有间歇fault，仍须按实际数据排查。三只固定超声波与编码器/IMU生成的是局部地图，不是全局闭环SLAM。

范围
只替换RK导航二进制。模型、摄像头、窗口、手机APK、FPGA、配置文件、配对码及两个启动脚本不变。
固定60527.7计数/圈与M1/M2/M3/M4编码器符号(-1,1,-1,1)不变，轮组继续依据已确认的实时FPGA ACK。
交叉编译使用现有BSP的GCC10.3。主机完成同步、回绕、真假故障、控制网关、安装回滚、实际A*固件离线联调；尚未在实体RK/小车验证。

板上安装和核对以安装包内“使用说明.txt”为准。
