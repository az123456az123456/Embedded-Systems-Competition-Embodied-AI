# ACG138 使用 AX210 连接手机

> 日期：2026-10-15；历史 PCIe 方案参考。用户已确认网卡通过 USB 接入，当前请使用 [USB 无线网卡联网说明](USB无线网卡联网说明.md)。下文不能用于判断 USB 网卡是否可用。

## 📡 安装与通信路径

本地 ACG138 BSP 手册描述的 AX210 方案为：**底板 J4 PCIe 接口 → 配套 PCIe 转 AX210 转接卡 → AX210 → 匹配天线**。安装、接天线和检查转接卡供电时先断电，不能只把网卡插在机械外形相似、接线不同的插槽。AX210 的 Wi-Fi 使用 PCIe，蓝牙还需要独立通路，本项目不依赖蓝牙。

历史资料确认过 AX210 的 J4 Gen2 x1 和 **2.4GHz 联网短测**；不能由此承诺任意系统镜像、5/6GHz、热点 AP 模式、任意 USB 无线网卡或蓝牙均可用。驱动和固件预装在资料包里，也不代表用户实物已安装网卡或当前系统已识别。

优先采用下面第一条连接路径：

| 连接路径 | 用法 |
|---|---|
| 同一路由器 | AX210 连接路由器 2.4GHz Wi-Fi，手机也连接同一路由器；关闭访客网络/客户端隔离 |
| 手机热点 | 手机开启 2.4GHz 热点，板子用 AX210 接入；部分手机热点或网络策略会阻止手机与客户端互访，需实际测试 |
| 有线先验证 | RK3588 外部 RJ45 接路由器，手机接此路由器 Wi-Fi；先验证 APK/视频/控制，再换 AX210 |

**手机通信与 FPGA 的 IMU 通信是两条独立网络。**外部 RJ45 的设备身份是 `fe1b0000.ethernet`，FPGA/IMU 内部 RGMII 是 `fe1c0000.ethernet`。启用内部 RGMII 后，`eth0`/`eth1` 的编号可能交换，不要照抄固定编号。无线接口也不保证叫 `wlan0`。

## 🔍 先运行只读诊断

在 RK3588 上执行项目目录下的：

```sh
sh scripts/diagnose-network.sh
```

脚本只查询，不改地址、不启动或重启服务，不读取 Wi-Fi 配置、不打印密码，也不打印可能含密码的进程完整参数。输出包含实际 PCI 设备、AX210 驱动绑定、固件文件、无线接口、IPv4、WPA 状态和 DHCP/网络管理进程名称。可以把这份输出用于继续判断；不需要提供无线密码。

| 看到的结果 | 下一步 |
|---|---|
| 没有 `8086:2725` | 先查 J4、转接卡、电源和网卡是否实际安装；固件文件不能解决没有 PCI 枚举的问题 |
| 有 AX210，没有 `iwlwifi` 绑定 | 核对当前内核驱动与匹配固件，查看诊断中的固件加载信息 |
| 已绑定但没有无线接口 | 结合内核日志、rfkill/平台状态和实际镜像继续排查，不要重复开 WPA |
| 有无线接口，没有 IPv4 | 先看 WPA 是否关联成功及已有 DHCP 管理器；不能直接启动第二个管理实例 |
| WPA `COMPLETED` 且有 IPv4 | 使用该地址启动服务端并填写 APK；再验证客户端隔离、防火墙和端口可达性 |

## 🔑 手动连接模板：仅在接口无人管理时使用

若诊断显示已有 `wpa_supplicant`、`dhcpcd`、`udhcpc`、NetworkManager、connman 或 iwd，先沿用现有管理方式，查它管理的是哪个接口。**进程存在不等于一定管理这张网卡；也不能因此随意停止全部网络服务。**资料镜像包含 `S40network` 和 `S41dhcpcd`，当前实际镜像应以诊断为准。

只有确认目标无线接口没有管理器，才使用以下临时方式。先创建仅自己可读的配置文件，再用板上编辑器填写自己的网络名和密码；不要把密码放在终端命令参数、聊天或日志里：

```sh
umask 077
touch /root/acg138-wifi.conf
chmod 600 /root/acg138-wifi.conf
```

配置模板如下：

```ini
ctrl_interface=/run/wpa_supplicant
update_config=0

network={
    ssid="你的2.4GHz网络名"
    psk="你的无线密码"
    key_mgmt=WPA-PSK
}
```

此模板用于 WPA2-Personal 网络。若路由器使用其他安全模式，配置应按该网络及当前 WPA 版本调整。完成后：

```sh
chmod 600 /root/acg138-wifi.conf
WIFI_IF=实际无线接口名
wpa_supplicant -i "$WIFI_IF" -c /root/acg138-wifi.conf
```

保持该前台进程，在另一个终端只读查询：

```sh
WIFI_IF=实际无线接口名
wpa_cli -i "$WIFI_IF" status
ip -4 addr show dev "$WIFI_IF"
```

`wpa_state=COMPLETED` 表示关联成功。若已有 DHCP 管理器，等待/使用该管理器获取地址；不要再运行下面命令。**仅当该接口既没有 IPv4 地址，也没有 DHCP 客户端在管理，且网络提供 DHCP 时**，在第二终端执行：

```sh
udhcpc -i "$WIFI_IF" -n -q
ip -4 addr show dev "$WIFI_IF"
```

这是临时获取地址，`-q` 成功后退出，不负责长期续租；长期使用应纳入已有网络管理配置。手动前台 WPA 按 Ctrl+C 会断开此无线关联。这里不自动创建启动服务，也不修改现有有线或 FPGA 内部网络。

## 📱 填写 APK 地址

板子连通后，例如无线接口地址为 `192.168.1.120`，在 APK 设置填写 `http://192.168.1.120:8080` 和服务端配对码。服务端要监听该可达接口或 `0.0.0.0`；仅监听 `127.0.0.1` 时手机无法访问。先看实时视频和 IMU，再使能电机。

APP 连接失败不必先换模型或重烧 FPGA：先区分没有关联、没有 IP、访客/热点隔离、服务端未启动、端口监听地址及配对码错误。手机和板子处于同一 SSID 并不能保证互相可达。
