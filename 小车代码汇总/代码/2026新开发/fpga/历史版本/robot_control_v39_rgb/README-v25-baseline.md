# ACG138 v25 超声波实际观测滤波与时间修复

本工程从冻结的 `robot_control_v24` 复制。只修改超声波解码、驱动传递和采集打包的4个合成文件。电机控制、编码器、摄像头、RGMII、IMU、A*软核、初始化固件、全部引脚CST和时序约束SDC保持逐字节一致。

## 修复内容

旧版较大远值必须彼此相差不超过200mm；车身转动时看见不同表面，可能连续拒绝正常有效值，最终显示过期或故障。v25采用滚动两帧保守最小值，不再要求两帧数值互相接近：

- 更近或相等的有效观测立即采用。
- 第一个较远值不能清除原近障，也不刷新原值的年龄；第二个有效较远观测确认后，采用两者较小值。
- 后续连续远值滚动确认；有效数字变化较大不再导致持续拒绝。
- 不再输出IIR计算得到的虚拟距离。输出总是一个实际收到的观测；若采用前一帧，SNS1会携带那一帧真实的年龄。
- CRC错误、0～29、65535、部分帧超时和在线转离线会打断确认链。断线恢复后，较远值需要两条新的有效观测；更近值仍立即生效。

SNS1仍为version1、保留字节63仍为0，字段、CRC、EtherType和接口引脚不变。采集模块使用新增的内部 `distance_age_ms`，不再因确认帧到来就把上一帧观测错误标成age0。编码器50ms窗口和即时超声波事件仍彼此独立。

## 远距和有效性

校验正确的30～4500mm保留有效数值；4001～4500mm由配套RK显示为 `>4m`。4501～65534按官方驱动习惯先钳到4500mm；65535保持无效。0、无回波、坏校验或断线都不会被制造成有效远距。

在线有效状态依据被采用观测的真实年龄，1s到期即失效；不会仅因收到新字节重新计时。500ms稀疏输出测试证明，采用前一帧时仍显示至少500ms年龄，不能伪装成新鲜值。运动时应核实模块实际输出周期，并使用经过确认的实时模式；本版没有放宽RK导航750ms、跟随500ms的测距时效要求。

## 工程与验证

打开 `robot_control_v25.gprj`，或执行：

```sh
GOWIN_COMPAT_CXX=/usr/lib/x86_64-linux-gnu/libstdc++.so.6 \
GOWIN_SH=/home/tan/qiansai/Gowin_V1.9.12.03/IDE/bin/gw_sh \
sh tools/build_softcore.sh
make test-release
```

位流：`impl/pnr/robot_control_v25.fs`。编译结果与完整回归状态以 `BUILD_STATUS.txt`、`reports/release_verification.json`、`reports/full-release-verification.json` 为准；后者绑定实际生产输入、测试输入、位流和日志的SHA256。

`reports/sonar-v25-sns.hex` 为实际UART→采集RTL产生的64字节SNS1载荷；`sonar-v25-sns-cases.tsv`注明场景。测试覆盖远值变化不饿死、单帧近障、原始超量程、无效值、真实观测年龄、500ms稀疏观测、时钟回绕和完整SNS1兼容。

原版背景保留在 `README-v24-baseline.md` 和 `README-v21-baseline.md`。离线仿真和声明约束下的内部STA不代表实体车验收，也不代表外部摄像头/RGMII板级IO已经完成物理签核。
