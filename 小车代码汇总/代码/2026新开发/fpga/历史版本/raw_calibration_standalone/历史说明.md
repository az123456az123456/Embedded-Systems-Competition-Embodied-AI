# 独立双目 RAW 标定采集工程

本工程用于导出两路 OV5640 的 **960×1080 RAW8** 帧，同时完成曝光、增益、白平衡的锁定和参数读回。它是临时工程，不修改 v40 图像工程。RK 接收程序位于同级仓库的 `rk3588/raw_calibration_standalone`，使用原生静态 ARM64 程序，不依赖 Python。

## 最短使用流程

1. 先退出 RK 上正在运行的 YOLO 窗口和旧摄像头 ISP 进程，避免同时占用链路和 CPU。临时工程不输出原来的 RGB 视频，也不运行 IMU、导航或手机服务；12 路电机 PWM/方向输出固定为 0。
2. 两个镜头同时朝向均匀亮场，保持光照、距离和焦点稳定。**此时不要盖镜头**。使用 Gowin Programmer 的 **SRAM 下载**加载 `bitstream/raw_calibration.fs`，不需要写 Flash。
3. 等待约 10 秒。传感器表初始化后自动运行约 5 秒，再锁定 AEC/AGC/AWB，静置 0.5 秒，两遍读回确认曝光/增益/WB 稳定。无需 RK 下发锁定命令。
4. RK 安装并执行下面的亮帧、暗帧命令。两组之间不要断电、重置 FPGA、重新配置摄像头或重新加载位流。
5. 拷回 RAW 和两个 JSON。完成后加载原生产位流并重启原摄像头服务。网络参数可用配套脚本恢复。

详细命令见 RK 工程的 `README.md`。采集电路没有接收控制命令的通路，不能用原 `fpc1.py` 对它发指令；这是刻意选择的最小实现。

## 锁定与读回

配置时钟 50 MHz；SCCB 使用原项目 400 kHz 控制器。完整保留原 v40 的 259 项 RAW8 初始化表，SHA256 为 `5004f1c0832d2fcb7134be513dfef7f9c90987294c079414a085fe0391ff9b21`，分辨率 960×1080，flip=1、mirror=0。

初始化后写 `0x3503 = 原值 | 0x03`，冻结自动曝光和自动模拟增益；写 `0x3406 = 原值 | 0x01`，冻结自动白平衡。各相机读回 64 个寄存器，覆盖芯片 ID、曝光、增益、WB 增益、输出格式、窗口、时钟和相关 ISP 控制。曝光/增益/WB 寄存器在第二遍逐项校验；错误会阻止 RAW 放行，发送错误元数据。

错误码：1=从机 NACK；2=芯片 ID 不为 0x5640；3=手动锁定控制位不正确；4=两遍锁定参数变化；5=内部状态错误；6=单次 SCCB 事务超过 20 ms。错误中保留失败寄存器地址。默认只锁定一次，改变亮场后若要重新选曝光，重新加载 SRAM 位流即可。

本临时工程没有加载自动对焦固件。它锁定的是曝光、增益、白平衡，不代表对焦或所有内部 ISP 自适应项均已冻结。测试机读回值是否符合真实传感器行为、物理 Bayer 相位和实物焦点仍需上板确认。

## 原始帧和链路

通路：DVP RAW8 → 原有行号封装 → 两个异步行队列 → 双目等行号配对 → UDP FIFO → CRC/UDP/Ethernet → RGMII。

- 图像数据不经 Demosaic、Gamma、缩放或 FPN，原始 8 bit 数据直接导出。
- 每路输入 FIFO 深度 16384 字节；网络输出 FIFO 8192 字节。
- RGMII TX 时钟 125 MHz；配置 50 MHz；传感器 PCLK 在约束中按 100 MHz 上限检查，真实频率待上板测量。
- UDP 端口：源 5000，目的 6102；源 MAC `00:0a:35:01:fe:c0`，目的广播；源 IP `192.168.0.2`，目的 IP `192.168.0.3`。
- UDP 负载 1922 字节：2 字节小端行号，CAM0 的 960 字节，再 CAM1 的 960 字节；大于常规 MTU，RK 内部接口需 MTU 4000。
- 保留旧 RAW 行协议，没有传感器源帧 ID；接收端严格接收连续 0～1079 行，缺行/乱序丢弃整帧。**只能用于静态标定，不宣称左右传感器曝光硬同步**。
- 行号 `0xffff` 为参数包，约每 100 ms 一次；图像尚未放行时也可读取启动或失败状态。
- 参数包前 152 字节为 CAL1/v1，含规格、锁定标志、状态、错误、失败地址和两路各 64 字节读回值，剩余负载补零。具体布局见 `rtl/raw_calibration_top.v` 和接收端 `Profile`。
- 参数快照在终态后不再变化；使用两级终态同步后采样到 TX 域，给快照路径保留 12 ns 最大延迟约束。FIFO 使用 Gray 指针同步及同步释放复位。

## 编译与验证

GUI 打开 `raw_calibration.gprj`，器件 **GW5AT-LV60PG484AC1/I0**。命令行完整编译：

```sh
python3 fpga/raw_calibration_standalone/build.py
```

默认从仓库 `Gowin_V1.9.12.03/IDE` 寻找工具，其他位置可设置 `GOWIN_IDE`。构建在独立临时目录冻结源码；内部 STA 通过后才复制 `.fs`，源文件与位流 SHA256 记录在 `reports/build.json`。工具授权仍按本机 Gowin 配置。

实编译结果：Logic 4372/59904，寄存器 5657/60780，BSRAM 26/118，DSP 0。内部 setup/hold 均无违例，最小 setup 余量 **+0.036 ns**，hold **+0.225 ns**。余量较小，结论仅限本次工具/器件/布局的内部时序；没有实物 DVP/RGMII 外部时序签核或上板采集验证，不应描述为已上板通过。

PC 仿真：

```sh
python3 fpga/raw_calibration_standalone/tests/run.py
python3 rk3588/raw_calibration_standalone/tests/run.py
```

第一条需要 Icarus Verilog、Verilator 和支持 C++20 的编译器。验证启动成功与五类失败、真实 SCCB 位级读写/重复 START/NACK、两路 DVP 经 FIFO 到 UDP 的两帧全尺寸数据，检查 4,147,200 个像素字节、Ethernet CRC、IP 校验和、元数据和 IFG。第二条用 BSP QEMU 执行交付的静态 ARM64 二进制，覆盖 19 个正常/异常场景。

另有本次生产网表的六种启动/锁定门级测试，见 `reports/gate-verification.json`；只跳过长时间等待，未绕过配置、ROM、读回比较或锁定逻辑。测试夹具在 `tests/tb_setup_gate.sv`，依赖本次合成实例名。完整布局布线报告和实际网表压缩文件一并保留。

## 采集参数与生产工程衔接

暗、亮帧必须来自同一次锁定会话。导出文件证明采集期间的锁定设置，不会自动改变生产工程。原 v40 重新启动会恢复其初始化流程和自动调整；直接使用标定表而不保持对应曝光/增益，不能保证 FPN 效果。

配套 PC 工具 `make_locked_runtime.py` 可根据真实亮帧 JSON，**复制**原 v40 工程到新目录并追加两眼独立曝光/增益/WB 写入项，不修改原工程。这个副本仍须完整重编译、检查时序、上板确认，并验证焦点、黑电平等条件。由于现在没有真实采集参数，本包不伪造对应的生产锁定参数和生产位流。
