# 构建与复现

所有命令以 `小车代码汇总/代码/2026新开发/` 为工作目录。本仓库提供应用和 FPGA 项目源码；芯片厂商 SDK、系统镜像、推理模型、签名文件等通过既有开发环境准备，禁止用 x86 共享库替换 ARM64 板端库。中文路径若不被 Gowin 支持，将整个对应工程复制到 ASCII 路径构建。

## 1. 主机检查

需要 Python 3.10+、GCC/G++（C11/C++17）、make、JDK 17、Icarus Verilog。检查不连接硬件、不发送运动命令：

```bash
python3 tools/verify_source_tree.py
python3 tools/run_smoke_tests.py
```

回归会将当前项目复制到临时目录，编译/测试结束后删除临时产物。修改源码后显式执行 `python3 tools/verify_source_tree.py --update` 更新文件清单，再执行默认检查并审阅差异。GitHub Actions 使用相同入口；它不证明 FPGA 时序或整车动态验收。

## 2. FPGA v54

工具：支持 `GW5AT-LV60PG484AC1/I0` 的 Gowin EDA（冻结记录为 V1.9.12.03）及对应许可；RV32IM/ilp32 裸机工具链（默认前缀 `riscv64-unknown-elf-`）。

```bash
cd fpga/v54_150_70_20261104
make -C softcore/firmware TOOLCHAIN=riscv64-unknown-elf-
gw_sh build.tcl
```

`make` 生成固件 ELF/BIN、ROM `firmware*.hex` 和 `firmware_symbols.vh`，再由 HDL 工程使用；这些输出不提交。`memory_profile.json`、链接脚本、RTL、CST/SDC 是构建输入，必须保留。`camera/ov5640_af.hex` 是传感器固定初始化输入，由 Git 历史恢复，与软核编译输出区分。`robot_navigation_v42_singlemap.gprj` 是沿用的内部工程名。

历史工程优先使用版本根目录的 `build.tcl` / `.gprj` / `Makefile`。`tools/baseline_v14/` 等目录是对比用配置/文件片段，不能把它们当成独立完整工程。实验版本不等同于最终 v54。源码包不提供重建位流必然逐字节一致的保证。

## 3. RK 原生主程序与网关

RK 宿主为 Linux 6.1.75 / aarch64 / Buildroot。使用与现有 BSP 匹配的 GCC、Wayland client 开发头/目标库、RKNN Runtime、RGA 和 libjpeg-turbo。

```bash
cd rk3588/v143_20261104/robot-fpga-integration-20261102
# 先设置 CROSS_COMPILE、WAYLAND_INCLUDE、WAYLAND_LIB、RKNN_INCLUDE、RKNN_LIB；
# 如需 RGA，设置 RGA_INCLUDE。路径来自匹配的 ARM64 BSP。
sh perception/scripts/build-arm64.sh FPGA_NAV=1
python3 tools/build_gateway.py   --compiler "${CROSS_COMPILE}g++" --static-cxx   --output "$PWD/bin/robot-fpga-gateway.aarch64"
```

主程序默认 JPEG=turbo，需要从原 SDK 提供 `perception/vendor/jpeg_turbo/Linux/aarch64/libturbojpeg.a`，或按其许可从 libjpeg-turbo 源码构建匹配版本；本库仅保留头文件/许可。主机小范围测试不需该静态库，统一回归脚本直接编译相关源文件。摄像头辅助 C 源码见 `camera-fastpath-highfps/`，需要相应 RKAIQ SDK、FakeCam/ISP 隔离运行环境及既有 BSP。实际摄像头启动脚本由板端导出到 `fpga-camera-isp-1080/`。

`robot-perception/` 保留板端辅助脚本；`robot-fpga-integration-20261102/semantic/build-native.sh` 是可选语义模式构建入口，额外需要 RKLLM/RKNN 头和目标库。模型、音频、IQ/ISP 运行资源及完整 SDK 不在仓库。

## 4. ROS 2 工作空间

Ubuntu 24.04 ARM64 / ROS 2 Jazzy 位于 RK 的 `/acg138-ros2/rootfs`。`rk3588/v143_20261104/ros2/` 保留板端 `/opt` 下的源目录结构。原脚本保留 `/opt/...` 绝对运行路径；应在匹配 rootfs 中恢复该布局，不能直接在 PC 上运行 chroot 部署脚本。

覆盖层顺序：`/opt/ros/jazzy` → `/opt/acg138_ros`（基础工作空间 install 别名）→ `acg138_exploration_20261102/install` → `acg138_semantic_20261103/install`。基础包包括 RPLIDAR、遥测与地图桥，探索层包括过滤器等，语义层包括 `explore_lite`、`acg138_semantic`、`acg138_frontier`、`acg138_ros_bridge`。

基础/探索工作空间需按其 `package.xml` 安装 ROS 依赖并执行 `colcon build --merge-install`；语义工作空间保留了板端 `build-ros.sh`（限并发、包选择）。`install` 不提交，应从源码构建。ROS 2 Jazzy、slam_toolbox、DDS、编译器和系统依赖不包含在本仓库。板端 entrypoint 固定使用 Fast DDS、Domain 37、SUBNET 发现；网络参数以实际网络配置为准。

## 5. Android v143

需要 JDK 17、Android SDK platform `android-35`、build-tools `35.0.0`。源码构建不用 Gradle；签名文件必须由持有人提供。

```bash
cd 上位机/v143_1.2.43_20261104
export ANDROID_SDK_ROOT=/path/to/android-sdk
export SIGNING_KEYSTORE=/path/to/existing-project.keystore
sh build-apk.sh
```

脚本输出在 `build/` 与 `dist/`。沿用原签名才能覆盖已安装同包名 APK；密钥不进 Git。脚本的现有调试签名约定见脚本本身。APK versionCode 56、versionName 1.2.43。配对信息在运行环境配置，不写入仓库。源码不附 SDK 或 APK。

## 6. 运行准备

先确认 FPGA 实际烧录版本、引脚/轮位、传感器安装、配对令牌、模型/运行库和 rootfs。不要把“最终 v54 源码存在”理解为板子已烧录此版。手机与 RK 同网，手机入口为 RK 可达 IPv4 的 HTTP 8080，网关本机后端为 8082；FPGA 板内 RGMII 与手机无线网络分别配置。启动时保持空闲；使用明确操作开启电机和任务，完成硬件验证后再记录结果。
