# vision_demo.py 改进清单（任务5/6）

> 生成日期：2026-09-11
> 针对文件：`小车代码汇总/代码/rk3588/vision_demo.py`
> 结论：**最大的问题不是模型，是只做了"感知"没做"执行"。** 任务5 要"跟随"、任务6 要"任务执行"，都是闭环控制，当前代码是开环（检测 → 打印 → 结束）。

## 优先级总览

| 优先级 | 范围 | 理由 |
|---|---|---|
| **P0** | 测距 + 状态机 + 串口看门狗 | 不做这三样，任务5/6 答辩立不住 |
| **P1** | 时间平滑、目标选择、光照标定、线程解耦 | 现场会翻车的点 |
| **P2** | ReID、语义指令、日志录像 | 创新分 + 稳定性分 |
| **P3** | 换模型、自定义训练 | 确认精度不够再动 |

## P0（必须做）

### 1. 目标测距
- [ ] 实现单目测距：`d = f · H_real / h_pixel`（检测框高度反推）
- [ ] 或接入 FPGA 侧超声波 / ToF 补一路距离
- [ ] `send_target()` 增加距离字段
- **为什么**：跟随要维持距离、"移动到附近"要判"多近算近"，没有距离到达判据无法定义

### 2. 任务6 状态机 ✅ 已实现
- [x] 新建 `task6_mission.py`，状态机 `SEARCH → LOCK → ALIGN → APPROACH → ARRIVE`
- [x] SEARCH：原地旋转扫描（旋转分区策略待定，先匀速转）
- [x] LOCK：连续 N 帧确认目标（`TemporalGate` 时序门控，借鉴 Security 仓库 RulesEngine）
- [x] ALIGN：转向使偏角归零
- [x] APPROACH：前进到距离阈值内（占位用框高比例判"近"，等 FPGA 超声波）
- [x] ARRIVE：停车 + 上报
- [ ] SEARCH 的分区旋转（每 30° 停一下）待接运动学后细化
- **为什么**：这是把散装能力串成"自主任务执行"的骨架

### 3. 串口看门狗 + 协议
- [ ] 与 FPGA 组确认真实协议（当前 `$T,...` 是占位）
- [ ] 加 CRC 校验
- [ ] 加应答 / 握手
- [ ] 加看门狗（RK3588 进程崩了 FPGA 要能停）
- **为什么**：无看门狗时，进程崩溃会让小车按最后一条指令一直跑 —— 事故级风险

## P1（现场会翻车，要早做）

### 4. 锁定状态时间平滑
- [ ] 连续 N 帧确认才算锁定 / 连续 M 帧丢失才判丢失
- [ ] 或置信度滑动平均
- **为什么**：单帧判定导致锁定状态疯狂闪烁

### 5. 目标选择策略
- [ ] 当前 `found_targets[0]` 改成按框面积（≈距离）或跟踪连续帧数选
- **为什么**：多目标时选中对象会随 YOLO 输出顺序乱跳

### 6. 光照标定
- [ ] HSV 阈值从写死改为现场可调（`--show-mask` 已有，补标定流程文档）
- [ ] 或让模型学习颜色，摆脱 HSV
- **为什么**：比赛场地灯光一变，"红色"可能判不出来

### 7. 采集 / 推理解耦
- [ ] 拆线程：读帧线程 + 推理线程（队列）
- **为什么**：RK3588 上读帧会阻塞推理
