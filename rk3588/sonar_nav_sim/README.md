# 三向超声波小车导航建图仿真

> 日期：2026-10-20。电脑端独立程序，前/左/右固定 A02YYUW、左右编码器和 IMU；不连接真实电机。

## 🚀 打开窗口

需要 Python 3.10 或更新版本。窗口使用 PySide6；核心仿真和无窗口运行只使用 Python 标准库，不需要 ROS、NPU、OpenCV、开发板或模型文件。

在解压后的程序目录打开终端：

```sh
python3 -m pip install -r requirements.txt
python3 run_sim.py
```

Linux 也可以运行 `bash run-linux.sh`；已经安装 PySide6 时跳过安装。系统 Python 与 Conda 是两个环境，依赖需要安装到实际启动程序的同一个 Python 中。Linux 可用 `NAVSIM_PYTHON=/path/to/python bash run-linux.sh` 指定解释器。

Windows 在本目录执行 `py -3 -m pip install -r requirements.txt`，然后双击 `run-windows.bat`。这是 Python 源码运行包，不是 Windows EXE。窗口可在 Windows 使用，但本次实际验证环境是 Linux。

没有桌面的终端可用：

```sh
python3 run_sim.py --headless --seconds 120 --export exports/first-run
```

## 🗺️ 窗口怎么用

| 操作 | 效果 |
|---|---|
| 开始探索 | 先静止估计陀螺仪零偏，再原地观察，随后自主选择观察点 |
| 暂停 / 空格 | 冻结仿真时间，再次点击继续 |
| 急停 | 清零运动指令并暂停仿真；点击开始后才能恢复 |
| 重置 / 场景 | 从空白地图重新开始，可选室内房间、开放场地、走廊 |
| 1× / 2× / 4× | 改变播放速度，物理与传感器仍按固定仿真步长运行 |
| 点击已知空地 | 在有车体通行空间、且与当前位置连通的空地规划目标；到达后停车 |
| 恢复自主探索 | 取消手动目标并继续选择探索观察点 |
| 显示真实环境对照 | 显示橙色真实障碍和真实小车，仅供比较；不参与导航 |
| 导出地图与记录 | 输出地图、参数、估计轨迹、摘要、传感器日志和当前地图截图 |

灰蓝色是未知，浅色是已探测空地，深色是累计证据形成的障碍；绿色为编码器和 IMU 估计的轨迹，紫色虚线为规划路径。地图百分比是固定地图范围内已分类的格子比例，不代表真实环境探索完成率。

无可达新观察点时显示“暂无可达边界”，不宣称整间房已探索完成。固定探头和保守通行规则可能留下一些未知区域。

## 🧭 算法实际做了什么

1. 模拟差速小车与圆形保守车体，左右累计编码器计数、轮子惯性、轮径差和打滑。
2. IMU 模拟陀螺仪 Z 轴角速度、零偏和噪声。先静止校准，再融合编码器转角与陀螺仪；不读取真实航向，不使用磁力计。
3. 前/左/右三路固定探头各有60°宽声束、3cm盲区、4.5m上限，按100ms采样和100ms交付延迟模拟。使用锥内13条射线的最近回波近似，并加入测距噪声与失效样本。
4. 建图根据传感器采样时刻的历史位姿更新概率栅格；回波沿弧带提供弱占据证据，不把宽声束当精确激光点。无回波、故障和超量程不清成空地。
5. 在已探测空地上给车体留出空间，寻找可达且附近仍有未知格子的观察点，用 A* 规划。路径不会穿越未知区域或对角夹角。
6. 前方接近障碍就停止前进、转向观察并重新规划；编码器/IMU无效、测距异常或过期时输出停车指令。

真实 A02YYUW 的 RX 悬空/高电平对应处理值输出，厂家说明响应约100～300ms；本程序100ms固定延迟是可调近似，不是实物实时性保证。三个传感器自动发射，实际串扰需要安装后验证，接收软件不能安排其发射顺序。参考：[DFRobot 型号参数](https://wiki.dfrobot.com/sen0311/)、[输出模式与协议](https://wiki.dfrobot.com/sen0311/docs/21651)。

**本程序是带噪声里程计＋粗略超声波建图＋自主探索原型，没有回环检测、全局重定位或地图匹配修正。** 长时间运行会积累位置和地图误差。显示真实环境对照时可以观察这种误差。仿真未包含镜面反射、声学串扰、温度声速、真实电机 PID 或所有地面打滑情况；不能用仿真零碰撞代替实车验收。

## ⚙️ 换成你小车的尺寸

复制 `config.example.json`，修改后启动：

```sh
python3 run_sim.py --config my-car.json
```

| 参数 | 默认假设 | 实车需要测什么 |
|---|---|---|
| `wheel_radius_m` | 0.035m | 轮子有效半径 |
| `track_width_m` | 0.26m | 左右轮中心距；四轮滑移转向需要实测有效轮距 |
| `ticks_per_revolution` | 1440 | 轮子输出轴一圈的实际累计计数，包含减速比和正交倍频 |
| `robot_radius_m` | 0.19m | 包住整车轮廓的保守圆半径 |
| `max_speed_m_s` | 0.22m/s | 低速探索上限 |
| `stop_distance_m` | 0.32m | 从前探头起算的停车距离，需按实测制动距离调整 |
| `sonar_latency_s` | 0.10s | 测量实际端到端响应；可试0.20/0.30秒 |
| `sonar_dropout` | 0.012 | 每次测距失效概率 |
| `seed` | 7 | 相同参数、种子和固定步长可以复现同一仿真 |

默认几何和编码器参数是假设值，不代表已测量你的硬件。三个探头安装偏置集中定义在 `navsim/model.py` 的 `Config.mounts`：前方朝0°、左侧+90°、右侧−90°。坐标约定为车头X、左侧Y、上方Z；地图X向右、Y向上，角度逆时针。

## 📦 导出与回放

| 文件 | 内容 |
|---|---|
| `map.pgm`、`map.yaml` | 三值占据地图及米/格分辨率、原点 |
| `map.json` | 底部原点的栅格 log-odds、观测次数、估计轨迹 |
| `map-view.png` | 窗口导出时保存的当前地图视图，无窗口导出不生成 |
| `summary.json` | 时间、已知面积、行程；仿真模式另含真值评分 |
| `config.json` | 此次参数 |
| `telemetry.jsonl` | 从本次重置开始记录的测距、编码器、IMU、已执行指令和估计位姿 |

默认传感器日志先写入临时目录。退出或重置前点击导出可保留记录。无窗口模式也可以用 `--record logs/run.jsonl` 指定持久路径。

```sh
python3 run_sim.py --headless --scenario corridor --seconds 300 --export exports/corridor
python3 run_sim.py --replay exports/corridor/telemetry.jsonl --export exports/replayed
```

回放逐帧读取记录中的时间戳和观测，重新估计地图、轨迹，不打开硬件或发出真实运动指令。回放当前为无窗口模式；记录中的指令用于判断当时是否静止，不能用来控制实物。

## 🔌 后续如何接硬件

导航入口是 `Navigator.ingest(SensorPacket)`，返回 `Command`；窗口、算法与传感器来源分开。`QueueHardwareIO` 提供线程安全有界队列、命令限幅和缺帧停车，供后续串口或网络接收线程调用。详细字段、编码器计数、时间戳同步和接入示例见 [硬件接口说明](docs/HARDWARE_INTERFACE.md)。

当前程序没有实际串口/网口传输实现，不修改现有 FPGA 位流、冻结 UART v2 或 RGMII 协议。真实接入时还需要测量左右轮速反馈、速度闭环、方向校准和独立看门狗。旧手机遥控反馈里的 PWM 不能充当轮速。
