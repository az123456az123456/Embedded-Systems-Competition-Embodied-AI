# 旧框架能力边界地图（2025 成品分析）

> 目的：摸清 2025 成品框架「能做什么、怎么通信、边界在哪」，为 2026 新功能开发定位扩展点。
> 说明：本分析基于仓库内源码逐模块阅读整理。

---

## 一、系统总架构（三个独立子系统）

```
┌──────────────────── PC ────────────────────┐
│  ① 视觉识别 (ultralytics-main)              │
│     摄像头 → YOLO/颜色检测 → 弹窗/点击/串口   │
│                                             │
│  ② USB 机械臂 (usb.arm)                     │
│     PyQt5界面 + 串口舵机控制 + 自动抓取       │
└─────────────────────────────────────────────┘
              （⚠️ 目前 PC 与小车【无】直接通信代码）

┌──────────────── 小车本体 ──────────────────┐
│  ③ FPGA 小车 (FPGA_pangu)                   │
│     紫光 Pango FPGA 独立运行                 │
│     串口协议已定义，但仓库内无 PC 端调用代码   │
└─────────────────────────────────────────────┘
```

**核心结论：**
- ✅ 已实现闭环：**摄像头 → 颜色识别 → 机械臂抓取**（PC 内部）
- ❌ **小车与视觉/机械臂之间没有打通**，小车靠板载传感器独立跑
- ➕ 2026 若要做「视觉引导小车+机械臂协作」，需要新增 PC↔FPGA 通信层 + 统一调度

## 二、FPGA 小车（FPGA_pangu）

### 2.1 硬件接口（顶层 XR_FPGA.v）
| 接口 | 说明 |
|---|---|
| clk_sys | 50MHz 系统时钟 |
| rx/tx + rx0/tx0 | 2 路 UART（rx1/tx1 可扩展） |
| scl_hand/sda_hand | I2C → PRJ7620 手势传感器 |
| led[3:0] | 4 个 LED |
| motor[3:0] + ena/enb | 双电机 H 桥 + PWM 使能 |
| servo[7:0] | **8 路舵机** PWM 输出 |
| IR[2:0] | 3 路红外（循迹/避障） |
| USE/UST | 超声波 echo/trig |
| SMG_Data[7:0] + Scan_Sig[5:0] | 数码管显示 |

### 2.2 串口下行协议（PC→小车，9600 波特）
帧格式：`FF [CMD] [P1] [P2] FF`（5 字节，取中间 3 字节）

| CMD | 功能 | P1 取值 |
|---|---|---|
| `0x00` | 手动运动 | 01前 / 02后 / 03左转 / 04右转 / 00停 / 05左前 / 06左后 / 07右前 / 08右后 |
| `0x01` | 舵机角度(0-179) | P1=舵机ID(1-8)，P2=角度 |
| `0x32` | 存储角度到EEPROM | — |
| `0x33` | 读回EEPROM角度 | — |
| `0x13` | 切换控制模式 | 01手势 / 02循迹 / 03避障 / 04雷达 / 07摇头避障 / 08雷达扫描 |
| `0x05` | HLED 灯 | 00开 / 01关 |

### 2.3 板载控制模式（ctrl_mode，自动运行无需上位机）
| 模式 | 传感器 | 行为 |
|---|---|---|
| 手动 | — | 串口指令驱动 |
| 手势 | PRJ7620 (I2C) | 手势 上/下/左/右 → 方向 |
| 循迹 | 3 路红外 | 沿黑线跑 |
| 避障 | 红外 | 检测到障碍转向 |
| 雷达避障 | 超声波+舵机7 | 摇头测距+避障 |
| 摇头避障 | 超声波 | 摆动超声波防撞 |
| 雷达扫描 | 超声波+舵机7 | 扫描并**上传距离** |

### 2.4 上行数据（小车→上位机）
- 24bit `send_data`，雷达模式下 = `{0x03, servo7_angle, Distance[7:0]}`
- 超声波距离单位 **mm**（13bit 计数，Dis_cnt/294 累加）
- 数码管可显示 Distance 和舵机7角度

### 2.5 关键参数
- 电机速度：11bit PWM，0~2047
- 舵机：20ms 周期，角度 0~179 → 占空比 `angle*555 + 25000`（50MHz 计数）
- 超声波距离分辨率：约 1mm/计数周期

### 2.6 边界 / 可扩展点
- ⚠️ **仓库里没有任何 PC→小车的串口发送代码**（协议已定义好，缺调用方）
- ➕ 新功能想让 PC 决策控制小车：加一个 `serial` 通信模块，按上面协议发命令即可
- ➕ 上行数据协议简单，可扩展（如加角度、模式、多传感器字节）

## 三、视觉识别（ultralytics-main）

### 3.1 现有能力
| 脚本 | 功能 |
|---|---|
| yanse.py / yansekongzhi.py | 红绿蓝 HSV 颜色检测 |
| tanchuang*.py | 检测到目标色→弹窗提醒 |
| yansejiancefanhui*.py | 检测到颜色→返回/触发动作 |
| shiping*.py | 视频实时处理 |
| gujia*.py / gujiashiping.py | 人体骨架检测 |
| dianji.py / tupian*.py | 电机/图片测试 |

### 3.2 边界 / 限制
- ⚠️ 大多是「**检测颜色 → 点击屏幕 / 弹窗**」，用 pyautogui 模拟点击，**不是**真正的硬件联动
- ⚠️ 大量重复脚本、硬编码（摄像头索引、HSV 范围、坐标），版本混乱
- 依赖 ultralytics 推理（需 torch，CPU 慢 GPU 快）
- ❌ 没有和 FPGA 小车 / 机械臂的成熟联动代码（除了机械臂 yanse.py 系列）

## 四、USB 机械臂（usb.arm）

### 4.1 舵机定义（6 路）
| ID | 名称 | 作用 |
|---|---|---|
| 000 | 底座 | 水平旋转，调 X 居中 |
| 001 | 大臂 | 前后够物 |
| 002 | 小臂 | 固定角度保视野 |
| 003 | 腕部 | 调 Y 到抓取位 |
| 004 | 旋转关节 | 固定 |
| 005 | 夹爪 | 开合抓取 |

### 4.2 协议（115200 波特）
`#<ID3位>P<PWM4位>T<时间4位>!`  例：`#001P1500T1000!`

### 4.3 现有自动抓取流程（yanse.py）
初始化 → 摄像头检测目标色 → 底座调整 X 居中 → 大臂 → 腕部调 Y → 夹爪闭合

### 4.4 边界 / 限制
- ✅ 有完整抓取闭环（颜色→定位→抓取）
- ⚠️ 只有「抓取」，**放下/搬运/放置流程不完整**（ui.py 里有放下逻辑但分散）
- ⚠️ PWM 初始值硬编码 1500，串口 COM5 硬编码
- ⚠️ 每次只处理**单一目标色**

## 五、给 2026 开发的启示（关键）

1. **基础打得不错**：FPGA 协议完整、机械臂抓取闭环可用、颜色识别可用
2. **最大的缺口**：三大子系统「各自为政」，缺一个**统一调度层**
3. **推荐扩展路径**（供参考，等你们题目）：
   - 打通 PC→FPGA 串口，让视觉决策直接控制小车
   - 视觉升级：多目标识别 / 目标跟踪 / 深度测距
   - 机械臂补齐「抓取→搬运→放下」完整动作链
   - 设计统一指令协议（一帧同时带 小车+机械臂 动作）
