# ACG138 双目摄像头＋IMU：20 FPS 测试与回退

> 日期：2026-10-19 · 配套当前三核 YOLO v10.1 · 保留模型和 1920×1080 分辨率 · 尚未实板验收

## 📦 文件怎么用

| 文件 | 放在哪里 / 用途 |
|---|---|
| `imu_camera_dual_1080_20fps.fs` | 在电脑上用 Gowin Programmer 烧录 FPGA；双目摄像头＋IMU，不含电机 |
| `camera-fastpath-20fps-rk3588-20261019.tar.gz` | 拷到 RK3588 的 `/root/`，按下面命令安装 |

本次只替换 RK3588 隔离摄像头目录中的 `isp-probe`，自动备份旧文件。当前 YOLO＋IMU 窗口、模型、`run-dashboard.sh`、`run-perception.sh`、`/root/run-yolo.sh`、内核和原 ISP 库均保留。无需重装系统。

## 🔧 1. 安装 RK3588 配套

先在运行窗口的终端按 Ctrl+C 退出 YOLO。将板端压缩包拷到 `/root/` 后，在板子逐行执行：

```sh
cd /root
tar -xzf camera-fastpath-20fps-rk3588-20261019.tar.gz
cd /root/camera-fastpath-20fps-rk3588-20261019
sh install-20fps.sh
```

安装器会校验文件、拒绝仍在运行的 YOLO 窗口、停止同目录的旧 ISP 接收进程，备份并替换二进制。记下输出中的 `Backup: /opt/fpga-camera-isp-1080/fps20-backup.XXXXXX` 实际目录，供回退使用。若 ISP 并非装在默认目录，使用 `ISP_DIR=/实际隔离目录 sh install-20fps.sh`。

包要求沿用已经跑通的最终 fastpath v4 隔离 FakeCam 库（5 ms pending RAW 轮询）。当前最新优化版本已使用该库；本次没有新增库。参考库校验值：

```text
bd20b922212d5b22cc155008772c5ee8efc49c34d031e35425d1691f3e8a27b6
```

这是 `/opt/fpga-camera-isp-1080/lib/librkaiq.so` 的参考 SHA256，不是系统 `/usr/lib` 中的 RKAIQ 库。请勿用原系统库覆盖该隔离库。

## 🎥 2. 烧录 FPGA

使用原来的下载方式和器件配置，选择本次 `imu_camera_dual_1080_20fps.fs`。建议先下载到 SRAM 测试；保持现有双目摄像头、IMU、RGMII 接线。位流未加电机功能。

如程序下载后没有重新初始化摄像头，按原工程的复位方式复位一次，再启动窗口。若掉电下载 SRAM 位流会丢失，应在测试时重新下载；是否写 Flash 由你的日常烧录方式决定。

## 📊 3. 先确认采集 20 FPS，再开识别

在板上先运行无识别预览：

```sh
cd /root/perception-dashboard
./run-dashboard.sh -0 --no-detect
```

横置显示时将 `-0` 换成 `-90`。稳定运行约 30 秒，终端 `PERF capture_fps` 和 `preview_fps` 应接近 20。另开终端读取：

```sh
grep 'V4L2_INTERVAL' /tmp/fpga-isp.log | tail -n 2
grep 'FASTPATH' /tmp/fpga-isp.log | tail -n 5
```

期望 `FASTPATH rx_fps` 和 `output_fps` 都接近 20（理论分频为 20.032 FPS）。`V4L2_INTERVAL requested_fps=20` 只是标称帧间隔，不能证明摄像头实际到了 20；新的接收程序会关闭专用 loopback 的补帧/超时图像功能。

然后 Ctrl+C 退出预览，启动识别：

```sh
cd /root/perception-dashboard
./run-dashboard.sh -0
```

原来使用的其他窗口参数可继续添加；横置仍用 `-90`。原 `yolo` 快捷命令也可继续使用。本次不改变 NPU 频率、核心分配或模型。

| 观察结果 | 含义 / 后续检查 |
|---|---|
| `rx_fps`、`output_fps`、`capture_fps` 都约 20 | 本次采集提速生效 |
| `rx_fps` 仍约 15 | 先确认新位流已成功下载并完成相机初始化；改标称 FPS 不会改物理采集率 |
| `rx_fps` 约 20，`output_fps` 明显较低 | 看 `isp_ms/output_ms`、专用库版本和板端负载 |
| `output_fps` 约 20，窗口采集较低 | 看实际视频节点、NV12 转换和窗口负载 |
| `incomplete/malformed` 连续增长、画面错行或撕裂 | 停止测试并回退；保留日志检查相机采样/行配对/RGMII链路 |

启动瞬间允许有少量累计丢行，重点看连续几行稳定日志是否继续增长。还需观察暗光亮度、条纹、左右图像及 IMU 更新是否正常。诊断包内 `sh diagnose-fps.sh` 仅读取状态，可一并保存输出。

请保留：无识别时 3 行 `FASTPATH`＋`PERF`，开识别后 3 行 `PERF`＋`STAGE camera_frame`＋`STAGE npu_worker`。这样能区分相机输入、ISP、窗口和识别的瓶颈。

## ↩️ 回退到原 15 FPS

先退出 YOLO，用安装器输出的真实备份目录替换下面的 `XXXXXX`：

```sh
cd /root/camera-fastpath-20fps-rk3588-20261019
sh rollback-15fps.sh /opt/fpga-camera-isp-1080/fps20-backup.XXXXXX
```

随后用电脑将完整工程包中 `rollback-15fps/imu_camera_dual_1080_imu_filter.fs` 烧回 FPGA，再运行原窗口。若安装时指定了 `ISP_DIR`，回退也指定相同值。**接收端和 FPGA 两端都回退，才恢复原采集配置。**

## ✅ 改动与验证边界

相机保持 960＋960 拼接，HTS=2500；系统分频 `3035:21→11`，VTS=1680，最大曝光=1676行，配套50/60Hz步长和夜景模式；PLL倍频 `3036=69` 保留。预计 PCLK 从42.067升至84.135 MHz，理论20.032FPS。259条初始化表及9位地址通过实际初始化仿真。依据 [OmniVision OV5640 规格书](https://files.waveshare.com/upload/d/da/OV5640_DataSheet.pdf) 和本地BSP时钟/曝光算法。

已完成 Gowin 综合、布局布线、内部时序检查（setup/hold均0违例）、46路引脚核对、双目1080行重组、发送间隔/CRC、复位、MPU9250和IMU滤波回归，以及RK3588交叉编译和接收/帧间隔/安装回退隔离测试。报告保留编译器原有告警。外部相机数据/PCLK板级时序和真实20FPS仍待上板测量。

链路预算约345.46 Mbit/s（加IMU约0.17 Mbit/s），有带宽余量；原FIFO无源背压、行协议无帧号、双目非曝光硬同步的限制保留。FakeCam仍使用原离线曝光描述，须实测亮度和稳定性。

现有模型三核每眼约100～110 ms，之前双目识别约14.3 FPS。此次目标是把采集/预览从15提高到20，并改善新图像供应；不能保证双目YOLO也达到20 FPS。
