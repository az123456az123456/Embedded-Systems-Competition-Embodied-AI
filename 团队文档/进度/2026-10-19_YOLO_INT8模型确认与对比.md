# ACG138 YOLO 模型确认与 INT8 对比

> 日期：2026-10-19 · 保留双目 1920×1080、20 FPS 采集和现有 YOLO＋IMU 窗口 · 新模型实板结果待测

## 🔎 已确认当前模型未启用 INT8 量化

用户板上 `/root/rknn_yolov8_demo/model/yolov8s.rknn` 的 SHA256 为：

```text
0b8359708f51941885f775f93bb98ac379016a2b913087af951c2028761ac47a
```

它与本地原始模型完全相同（24,010,196 字节）。原转换脚本明确使用 `rknn.build(do_quantization=False)`，编译器为 RKNN Toolkit2 `2.0.0b0+9bab5682`；内嵌边界元数据也没有量化参数。因此可确认当前这份模型没有启用 INT8 构建量化。此结论由文件身份与构建证据共同支持，不是仅凭 FP16 输入输出推断。

## 📦 交付内容

板端包 `acg138-model-compare-int8-20261019.tar.gz` 包含两个实际转换完成的模型和独立切换脚本：

| 选择参数 | 使用的模型 | 作用 |
|---|---|---|
| `--variant v8-current` | 板上当前 YOLOv8s | 保留原文件，作为对照 |
| `--variant v8-int8` | 本包 YOLOv8s INT8 | 使用原始 ONNX/权重，检验量化效果 |
| `--variant v11-int8` | 本包 YOLO11s INT8 | 瑞芯微优化模型，检验换模型效果 |

输入均为每只眼 640×640 RGB；完整预览仍是 1920×1080，双目均进行识别。三个选项使用同一个已安装的 v10.1 窗口、IMU 和摄像头链路。新模型使用与原模型相同的 RKNN 2.0 编译工具链；本次包未附新运行库，也不替换系统库。

无需重新编译窗口或再烧录 FPGA；继续使用已经测到 20 FPS 的位流和接收程序。原 `yolo`、`run-dashboard.sh` 入口仍使用原模型，只有新对比入口选择新模型。

## 🔧 拷到板子并校验

先退出当前 YOLO 窗口。将压缩包拷到 RK3588 `/root/`，逐行执行：

```sh
cd /root

cd acg138-model-compare-int8-20261019

```

所有文件应显示 `OK`。板上只需原有 Shell 与运行环境，不需要安装 Python 或 RKNN-Toolkit。

可以再次只读核验原模型：

```sh
sh scripts/inspect-current-model.sh /root/rknn_yolov8_demo/model/yolov8s.rknn
```

## 📊 按同一条件测试三个选项

将小车放在同一位置，保持光照和画面基本不变。每次只开一个窗口，运行约 60 秒；下面命令会自动结束该窗口，并把输出保存为日志：

```sh
cd /root/acg138-model-compare-int8-20261019
./run-model-compare.sh -0 --variant v8-current --seconds 60 2>&1 | tee v8-current.log
./run-model-compare.sh -0 --variant v8-int8 --seconds 60 2>&1 | tee v8-int8.log
./run-model-compare.sh -0 --variant v11-int8 --seconds 60 2>&1 | tee v11-int8.log
```

横置显示时把每条的 `-0` 全部改为 `-90`。三个模型也可不带 `--seconds` 长期开窗，Ctrl+C 退出。默认统一使用双目、3 个 NPU 工作线程、置信度 0.35、NMS 0.45；若追加自定义参数，三次使用相同参数。

重点比较稳定后的 `PERF result_fps`、`inference_ms`、`box_age_ms` 和 `STAGE npu_worker`。`capture_fps` 应仍接近 20；画面预览 FPS 和重复使用旧识别框都不等于新增识别结果 FPS。若 `result_fps` 接近 20，此时当前采集频率就成为上限。

也要实际看漏检、误检及框位置，特别是远处、小物体和暗处。性能日志本身不能量化识别精度。

可把三份日志拷回电脑，在有 Python 3 的环境汇总：

```sh
python3 scripts/summarize-comparison.py v8-current.log v8-int8.log v11-int8.log --json comparison.json
```

汇总器分别跳过每次运行前 5 条 `PERF`，给出样本数、FPS 与图像/框年龄的中位数和范围。若板子已装 Python 3，也可直接在板上执行。请将三组稳定日志发回，才能判断本板速度差异。

## ✅ 已完成与限制

两个模型均实际执行 `do_quantization=True` 构建，启用 INT8 量化；保留标准归一化 mean=0/std=255，以及瑞芯微 9 输出检测格式。ONNX 结构、输出形状、归一化、RGB 顺序及 114 字母框校准已检查；每个模型在电脑 RKNN 模拟器上运行 3 张图片，9 个输出形状、有限值和概率范围通过检查。模型哈希、校准图片哈希、构建日志和测试证据随包提供。

两者采用同一批 20 张 COCO 图片进行初步量化校准，不是小车实拍校准集，也不是有标注的独立精度验证集。编译器均提示权重离群值，可能影响量化精度；完整告警保留在日志中。需要用本车画面检查漏检与误检，不能从“转换成功”推断精度保持。

当前 RKNN 2.0 工具链把 YOLO11 的部分注意力处理（Gather 和 Softmax）安排在 CPU，可能影响速度；YOLO11s INT8 不保证比 YOLOv8s INT8 快。建议先试 v8-int8，量化与原模型只有一项主要变化，便于判断收益。此处“INT8”表示启用 INT8 构建量化，不保证每个内部算子均为 INT8 或全部在 NPU 执行。
