# 2026 选题三：需求分析 + 旧框架对照

> 选题：**基于 FPGA 的具身智能机器人实时感知与自主控制系统设计**（高云半导体赛道）
> 依据：`文档/2026比赛指南.pdf`（22 页）

---

## ⚠️ 最关键的结论（先说）

**旧框架（紫光同创 Pango）与新比赛平台（高云 Gowin）不兼容！**

| | 旧框架 2025 | 2026 比赛要求 |
|---|---|---|
| FPGA 厂家 | 紫光同创（盘古/Pango） | **高云（Gowin）** |
| EDA 工具 | Pango Design Suite | **高云云源 GowinEDA** |
| 目标板卡 | 自研小车板 | **小梅哥 ACG720 / ACG750 / BX72 / ACG138-RK3588** |
| 芯片 | GW2A 系（约 55K） | GW5AT-138K / 60K |

- ✅ **Verilog 源码逻辑可参考/移植**（标准语法，换个平台重新综合即可）
- ❌ **工程文件、引脚约束、IP 核需要全部重建**
- ✅ **机械臂代码、视觉代码、协议设计思路可完整复用**（与 FPGA 厂家无关）

## 一、选题三任务清单（逐条）

### 基础要求（仅 FPGA + 软核 CPU 即可）
| 任务 | 内容 | 旧框架是否覆盖 |
|---|---|---|
| 任务1 多传感器感知 | 摄像头采集+图像显示；IMU 姿态采集；实时显示画面+姿态角 | ❌ 全新（旧框架无摄像头/IMU/显示） |
| 任务2 运动控制 | 前进/后退/转向/定点旋转；**编码器反馈闭环** | ⚠️ 部分（有电机 PWM 控制，**无编码器计数、无闭环**） |
| 任务3 实时避障 | 超声波/TOF/激光；检测→减速→停车→绕障 | ⚠️ 部分（有超声波测距+避障，需改造为分级避障逻辑） |
| 任务4 自主导航 | 起点到终点自主移动；避障；路径点导航 | ❌ 全新（旧框架无导航/定位） |

### 拓展要求（允许 RK3588 等边缘 AI）
| 任务 | 内容 | 旧框架是否覆盖 |
|---|---|---|
| 任务5 视觉目标识别 | 目标检测/跟踪；人员/物体识别；目标跟随 | ⚠️ 部分（有颜色检测，**需升级为 YOLO 目标检测/跟踪**） |
| 任务6 智能任务执行 | 目标搜索；语义导航；自主执行（如找到红色水瓶并移动过去） | ❌ 全新（需视觉→决策→运动全链路） |

### 评分重点
| 项 | 占比 |
|---|---|
| FPGA 实时感知与控制 | **40%** |
| 系统稳定性 | 25% |
| 自主导航能力 | 20% |
| 创新设计 | 10% |
| AI 扩展功能 | 5% |

## 三、建议的系统架构（方向）

```
┌────────────── 感知层 ──────────────┐
│  摄像头 OV5640 → FPGA 图像采集/显示 │
│  IMU (MPU6050) → 姿态解算           │
│  超声波/TOF      → 避障测距          │
│  编码器          → 里程计/速度闭环    │
└──────────────┬─────────────────────┘
               │
┌──────────────▼── 决策层 ────────────┐
│  高云软核 CPU（RiscV）:              │
│   - 数据融合 / 状态机 / 路径规划      │
│   - 与 FPGA 逻辑协同（AXI 总线）      │
│  [可选] RK3588 边缘 AI: YOLO 目标识别 │
└──────────────┬─────────────────────┘
               │
┌──────────────▼── 执行层 ────────────┐
│  FPGA 实时控制: 电机 PWM/闭环/舵机    │
│  运动底盘: 前进/后退/转向/定点旋转     │
└────────────────────────────────────┘
```

## 六、板卡已定：ACG138-RK3588-CORE 专属架构方案

> 更新：2026-09-11，队伍已确认拿到 **小梅哥 ACG138-RK3588-CORE**（RK3588 八核 + 高云 GW5AT-60K FPGA 异构平台）

### 6.1 板卡资源（依据选题指南）
- **RK3588**：8 核（4×A76 + 4×A55）、NPU 6TOPS、LPDDR4X、eMMC
- **高云 GW5AT-60K FPGA**：60K LUT4、DSP、BSRAM，适合实时控制与图像处理
- **接口**：MIPI 摄像头输入、HDMI/DP 输出、USB2.0/3.0、Type-C、PCIe 3.0 x2、PCIe 2.0/SATA、RGMII 千兆网、多路 GPIO
- **选配外设**：OV5640/OV5647 摄像头（也可双目）；电机驱动、姿态传感器等自选

### 6.2 建议的软硬分工（异构协同）
| 层 | 处理器 | 负责内容 |
|---|---|---|
| **实时控制层** | FPGA (GW5AT-60K) | 编码器正交解码、电机 PID 速度/位置环、PWM 驱动、超声波避障、IMU 读取（I2C/SPI）、与 CPU 通信 |
| **感知增强层** | FPGA (可选) | 图像预处理（灰度/二值化/ROI）、多路传感器时序、硬件加速 |
| **决策规划层** | RK3588 + Linux | YOLOv8 目标检测/跟踪（NPU）、路径规划（A*/DWA）、语义导航、任务调度、人机交互、实时显示 |
| **通信桥** | FPGA↔RK3588 | 见 6.3（待确认接口） |

### 6.3 ⚠️ 关键待确认：FPGA ↔ RK3588 互联方式
这是选题三核心「FPGA 与边缘 AI 协同」的**技术命门**，取决于板卡手册，常见三种：

| 方式 | 带宽 | 适用 |
|---|---|---|
| UART (115200~几Mbps) | 低 | 控制指令、状态回传（最简单，够任务2/3/4） |
| SPI | 中 | 批量传感器数据、图像小块 |
| PCIe 3.0 x2 / 共享总线 | 高 | 高速视频流、大数据交互（最强，也最复杂） |

> 拿到板卡手册后需第一时间确认。若手册未写明，可直接找小梅哥技术支持确认。

### 6.4 摄像头链路（任务1 + 任务5）
- **方案 A（推荐）**：MIPI 摄像头 → RK3588（视觉识别 + 显示），FPGA 独立负责控制环 → 通信桥交换"目标位置指令"
- **方案 B**：MIPI 摄像头 → FPGA（采集/预处理/显示）→ 经通信桥把图像/目标信息给 RK3588
- 取决于板卡 MIPI 是接到 CPU 还是 FPGA（手册确认）

### 6.5 任务映射到新板卡
| 任务 | 实现载体 | 说明 |
|---|---|---|
| 任务1 感知 | FPGA(IMU+编码器) + RK3588(摄像头显示) | 画面+姿态角实时显示在 HDMI |
| 任务2 运动控制 | FPGA | 编码器闭环 PID，前进/后退/转向/定点旋转 |
| 任务3 避障 | FPGA + 超声波/TOF | 检测→减速→停车→绕障，实时性由 FPGA 保证 |
| 任务4 导航 | RK3588 规划 + FPGA 执行 | 里程计=编码器+IMU 融合，路径点导航 |
| 任务5 目标识别 | RK3588 + NPU | YOLOv8 目标检测/跟踪/跟随 |
| 任务6 任务执行 | RK3588 决策 + FPGA+机械臂 | 找到红色水瓶→移动→（可选）机械臂抓取 |

### 6.6 需要的开发环境（下一步搭建）
1. **高云云源 EDA**（GowinEDA）→ 建 GW5AT-60K 工程，跑通 LED/串口
2. **RK3588 Linux SDK**（小梅哥提供）→ 跑 Ubuntu + Python/C++ 环境
3. **通信桥测试** → 先在 RK3588 与 FPGA 之间打通一条串口/SPI
4. **底盘选型** → 电机+编码器+驱动（建议带 AB 相编码器的直流减速电机）
5. **IMU 选型** → MPU6050 / ICM-42688 / BNO055（I2C/SPI 均可）

### 6.7 开发里程碑（建议）
- **M1**（第1-2周）：云源EDA + 板卡点灯 + 串口通 + RK3588 系统跑通
- **M2**（第3-5周）：任务1 摄像头+IMU 显示；任务2 电机闭环
- **M3**（第6-8周）：任务3 避障 + 任务4 导航闭环
- **M4**（第9-11周）：任务5 YOLO 识别 + 任务6 语义任务
- **M5**（第12周+）：稳定性测试、创新点打磨、文档/演示
